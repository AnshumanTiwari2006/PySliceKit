# PySliceKit: The Machine Learning Auditor

## What is PySliceKit and Why is it Valuable?

### The Layman's Explanation (The "Why")
Imagine you build a spam filter for your email. Overall, it boasts a 95% accuracy rate. Sounds great, right? But what if you look closer and discover that for emails containing the word "Urgent", the accuracy drops to 40%? Your model isn't actually good; it's just "mostly" good, and hides its failures in the average.

**PySliceKit** is an automated detective for Machine Learning models. Instead of just looking at the "overall average" score of a model, it automatically cuts (or "slices") your data into hundreds of different segments (e.g., "Age > 50 and Income < $30k"). It tests your model on every single one of those specific groups to find the hidden pockets where your model is secretly failing. It then visualizes those failures so you know exactly what needs fixing before you release your AI to the real world.

### The Technical Explanation (The "Value")
In production ML, global metrics (like overall F1 or RMSE) are dangerous because they mask algorithmic bias, data drift, and localized underfitting. Finding these edge cases manually by writing group-by statements in pandas is tedious, error-prone, and doesn't scale. 

**PySliceKit** provides automated **subpopulation analysis**. It:
1. **Bins** continuous features into statistically sound quartiles automatically.
2. **Generates combinations** (cross-products) of features (e.g., Depth 1: just Age. Depth 2: Age + Geography).
3. **Applies rigorous statistical testing** (Z-tests, Fisher's Exact, Bootstrapping) to ensure that a drop in performance isn't just random noise due to low sample size.
4. **Enforces a strict UI contract** where "Red always means bad", handling the complex logic of whether a metric needs to go UP (Accuracy) or DOWN (MAE) to be considered "good".

## File-by-File Technical Breakdown

### 1. `api.py` (The Conductor)
* **What it does**: This is the main entry point for the user. It exposes the `evaluate()` function.
* **How it works**: It orchestrates the entire library. It takes the user's dataset, their model predictions, and their configuration (like `depth=2`). It first passes the data to `validators.py` for safety checks, hands it to `slicer.py` to create the groups, passes those groups to `stats.py` to get the math done, and finally sends the results to `renderer.py` to draw the charts.

### 2. `types.py` (The Contract)
* **What it does**: Defines the core data structures that the rest of the library relies on. 
* **How it works**: 
    * It defines the `SliceResult` dataclass, which is the standardized object holding the segment name, the number of samples (`n`), the metric score, the gap from the baseline, and the p-value.
    * It defines the `MetricDirection` registry. This is crucial: it maps metrics like "accuracy" to `HIGHER_IS_BETTER` and "mae" (error) to `LOWER_IS_BETTER`. This ensures the renderer always paints the right things Red or Green.

### 3. `validators.py` (The Bouncer)
* **What it does**: Ensures the library never crashes with cryptic errors mid-execution by validating user input instantly.
* **How it works**: It checks that `y_true` and `y_pred` are the same length as the dataframe. It ensures the chosen `slice_cols` actually exist in the dataframe. It prevents the pipeline from proceeding if arrays are entirely made of `NaN` (Not a Number) values.

### 4. `slicer.py` (The Engine)
* **What it does**: Takes the raw dataframe and chops it into distinct groups based on the features the user selected.
* **How it works**: 
    * If a column is categorical (like `ocean_proximity`), it leaves it alone. 
    * If a column is continuous/numeric (like `HouseAge`), it uses pandas `qcut` to bin the data into 4 statistical quartiles (e.g., `Q1`, `Q2`, `Q3`, `Q4`). This prevents infinite slices.
    * If the user asked for `depth=2`, it uses `itertools.combinations` to pair columns up (e.g., `HouseAge` AND `ocean_proximity`) and creates cross-product segments. It yields masks (boolean arrays) that the next module can use to filter the data.

### 5. `stats.py` (The Mathematician)
* **What it does**: Computes the actual performance scores and runs statistical significance tests.
* **How it works**: 
    * For each segment generated by `slicer.py`, it calculates the metric (e.g., F1, MAE) using `scikit-learn`.
    * It calculates the **gap** (Segment Metric minus Overall Baseline Metric).
    * It runs **Hypothesis Testing**:
        * If it's a classification task with large sample sizes ($n \ge 30$), it runs a **Proportion Z-Test**.
        * If it's a classification task with tiny samples ($n < 30$), it uses **Fisher's Exact Test** because Z-tests break down on small sample sizes.
        * If it's a regression task, it uses a **Bootstrap Confidence Interval** to resample the data and see if the gap is statistically real or just random variance.

### 6. `renderer.py` (The Artist)
* **What it does**: Turns the mathematical output into beautiful, interpretable Matplotlib charts.
* **How it works**: 
    * Uses a unified color theme relying on `_severity_color()`: It checks `types.py` to see if a positive gap is "Good" or "Bad", and dynamically paints the shapes Red (Underperforming), Green (Overperforming), or Grey (Neutral).
    * It builds a **Heatmap** for 1D slices (1 column) vertically stacked.
    * It builds a **Ranked Bar Chart** for multi-column combinations, strictly sorted by absolute gap severity (so the most broken segments are always at the top).

### 7. `exporter.py` (The Secretary)
* **What it does**: Allows the user to save the audit results to disk for reporting or further analysis.
* **How it works**: It unpacks the `SliceResult` dataclasses and safely formats them into standard `CSV` or `JSON` formats.

### 8. `exceptions.py` (The Communicator)
* **What it does**: Defines custom error types (like `PySliceKitNoSegmentsError`).
* **How it works**: By having custom exceptions instead of generic Python `ValueErrors`, we can give the user highly specific, helpful instructions (e.g., *"All segments dropped because they have n < min_samples, try lowering min_samples"*).

## Summary
PySliceKit takes the deeply technical and statistically complex process of **subpopulation auditing**, handles all the math, grouping, and hypothesis testing internally, and outputs visual proof of model failures. It guarantees that models deployed to production are robust across *all* user profiles, not just on average.
